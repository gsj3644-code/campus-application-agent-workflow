# 公司岗位普查

本 Skill 在独立对话中完成事实采集，主要使用 GPT-6 Luna、Max 思考强度；模型由对话设置决定。产物是完整岗位供给和招聘规则，岗位取舍留给第二阶段。

## 范围与入口

确认公司、本届招聘项目、开放状态和扫描范围；读取工作区既有城市偏好，用于地区覆盖统计。复用同公司同届可信底表时核验时效与来源。以公司官网、官方 ATS 和本届公告为主要事实来源，分别确认总部、分支与子公司入口。

按 [官方站点遍历与覆盖验收](references/site-traversal.md) 枚举岗位；网页操作使用 `agent-browser`，公开结构化数据可直接获取。记录入口、分页终点、分面与回扫结果，以稳定 Job ID 去重。原始 JSON 可用 `scripts/normalize_jobs.py` 做并集和数量核对。

## Job Census

每条岗位记录公司、项目、岗位名与编号、机构、地点原文、人数、学历与专业、完整职责与任职要求、证书、截止时间、状态、官方链接和采集时间。关键字段保留官方证据；未披露、无法读取或表述含糊的内容标明缺口。岗位人数沿用岗位级数据。

可增加由 JD 支持的销售／获客、编程、财务建模、轮岗、异地及证书等事实标签；按“明确有／明确无／未披露”记录。保留来源冲突，字段约定见 [底表与交接](references/census-and-handoff.md)。

同阶段查明本届投递规则：可申请岗位数、志愿顺序、跨机构限制、修改／追加规则及不同机构的截止时间。记录来源和核验时间；登录后才能看到的规则明确标为待核。这里记录规则事实，下一阶段据此配置志愿。

## 交付

以**可筛选 Excel** 交付完整 Job Census：每个唯一岗位一行，列出上述事实并能查看完整 JD；可用单独详情工作表承载长文本。按 `spreadsheets` Skill 制作与验证，核对行数、编号、链接和代表性 JD。原始 JSON 可另存以便追溯。

最终回复直接给出 Excel 链接、岗位数量与偏好地区覆盖、已查到的投递规则、重要缺口，以及一句可复制的交接提示。覆盖明细与证据放在底表或随附文件。交接提示只需指出 `$application-portfolio-strategy`、完整底表与候选人资料的位置，以及本次特殊要求；第二阶段直接使用这份底表。
