# Word 交付核对

父代理写完正文并完成逻辑与投递规则自查后，让 Luna Max 子代理校对事实、制作 Word、渲染并逐页检查。子代理发现与底表或决定冲突时交父代理裁决。正式志愿数量与顺序对应本届规则；规则待确认时清楚写出条件方案。

1. 最终投递方案：系统顺位（存在时）、岗位名称、Job ID、地点、定位、选择理由、主要风险及官网链接。
2. 投递组合逻辑：岗位供给和候选人位置、每项加入后增加的机会、共同失败风险、未选相似岗位的理由、业务／销售岗位的实际作用。
3. 补充志愿表：**所有**未进入正式方案的重点候选岗位，含岗位、地点、ID、定位、现实可达性、保留理由、主要风险、未入正式志愿原因。重点候选池由第二阶段从完整底表形成。
4. 关键替换条件：仅写可能改变当前组合的信息，明确“若 X 得到证实，正式志愿 Y 改为 Z／追加 Z”。

事实核对：正式与补充岗位的名称、编号、机构、地点、岗位级人数、开放状态和截止时间与第一阶段底表一致；说明竞争推断的依据与关键未知项。Luna 渲染后逐页检查版面，确保表格可读、无错列或截断。父代理最后只读 Word 正文，核对正式志愿、顺序、岗位定位和替换条件与已定方案及本届规则一致。最终交付 Word 和第一阶段原有的完整 Excel 底表；Word 聚焦投递方案，Excel 供查看全部岗位与完整 JD。正文与交付说明用自然、直接、逻辑顺畅的中文，保留足够的判断依据。
