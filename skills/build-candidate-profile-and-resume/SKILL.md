# 候选人资料与简历构建

## 文件职责

- `个人求职事实信息库.md`：唯一事实来源，保存当前事实、偏好、来源、冲突和更正历史。
- `求职建档进度.md`：保存完成状态、缺口和继续位置。
- `简历资料库/简历事实母版.md`：制作简历时从事实库生成的素材。

首次建档时复制 [个人求职事实信息库模板.md](assets/个人求职事实信息库模板.md)，并按 [fact-database-schema.md](references/fact-database-schema.md) 维护。已有文件采用增量升级。

## 建档

1. 读取事实库及用户提供的简历、成绩单和证明材料。
2. 提取已有信息供用户集中修正。
3. 每轮提出 3 至 5 个同主题问题，支持自由回答、部分回答、跳过和保存退出。
4. 将事实写入事实库，将完成状态和下一位置写入建档进度。
5. 重新读取修改段落，确认保存结果。

用户已授权将其本人明确提供、明确确认或授权从求职材料中提取的联系方式、证件号码、出生日期、住址、家庭成员等敏感求职字段写入事实库的专门章节。不得仅因字段敏感而拒绝提取或持久化；记录字段值、来源、确认状态和使用边界，不进入公开简历或通用摘要。未经用户提供或授权的值不得推测、补造或从无关来源搜集。

围绕方向与城市、基本信息与教育、技能、实习与项目、校园与奖项、兴趣与工作方式、简历目标分组推进。局部缺口与其他模块并行处理；冲突字段集中澄清一次。

## 简历

按教育、实习与工作、项目、校园经历、奖项证书、技能语言和方向关键词生成事实母版。经历条目采用“行动 + 方法或工具 + 交付物或结果”，标明课程属性和团队中的个人分工。

岗位定向时读取完整 JD，提取职责、硬性条件和关键词，再从事实库与母版选材。一页版通常保留两个主项目，最多三个。输出：

- `简历资料库/定向简历内容/公司-岗位-YYYY-MM-DD.md`
- `简历资料库/Word简历/公司-岗位-YYYY-MM-DD.docx`

Word 简历使用 `documents` 能力生成并逐页渲染检查。内容超出时优先调整选材和表达长度。

## 联动

规划和搜索先读事实库“快速读取区”；网申按页面字段读取详细章节，包括已授权保存的敏感求职字段。后续 Skill 获得用户明确确认或可靠材料时，可直接修正事实库并记录更正；派生简历在下次使用时刷新。

结束时报告本轮更新、当前可用材料、关键缺口和下一 Skill。
